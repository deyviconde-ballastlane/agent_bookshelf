# Week 2 decision log

I split the work by role, not by resource. A first draft had one auditor per API resource, but `api.ts` is 243 lines: four auditors would each re-read the same file and CLAUDE.md, paying the same prefix four times without the parent's cache, and the design would grow to one agent per resource. Instead, five generic agents each own one job and one tool set. The auditor only reads, the test-writer only edits `tests/`, the fixer only edits `src/`, and the test-runner only runs the suite. The task itself lives in the briefs the `/audit-fix` skill writes, so the same agents can audit another rule or another folder. It is a pipeline with no barrier, because with one auditor there is nothing to merge, and every finding has to fail a test before the fixer touches it. Moving the subagents from Opus to Sonnet (Haiku for the test-runner) cut the run from $2.17 to $0.93, and the subagents' share from $1.46 to $0.33. It wasn't free: the Sonnet auditor made 4 requests instead of 12, found 12 issues instead of 15, and one real bug (`POST /api/shelves/abc/books`) survived. Next time I would put only the auditor back on Opus, since finding bugs is the step that needs reasoning and it costs about $0.40 more, and I would look at the orchestrator next, which is now 63% of the bill.
